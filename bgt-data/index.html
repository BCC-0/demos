Making walking networks from BGT data

Skeletonizing BGT polygons gives clean centerlines almost everywhere. Some situations break that. This page covers the ones found so far, with a proposed fix for each. Expect more to turn up.

What already works

Inside walkable polygons, skeletonization finds centerlines that follow where a person can actually walk (purple lines). Courtyards, pavements and plazas all come out well.

Problem cases found so far

"Sidewalks" in between roads

The strip between the carriageways is not road in the data, but it is tagged voetpad like any real sidewalk. Nothing in the attributes tells it apart, so it ends up in the network as a normal walking route.

ProblemYou must not walk along it, but the router will happily send people there.
Fix: neighbour filter in skeleton cleanupIf every neighbour of a sidewalk polygon is a road, it is a sidewalk-between-roads. Keep it only as a crossing point (for hopping between the two sides). Do not use it as a normal sidewalk.

Relative levels are very flexible

The orange lines should all be level 1. Yet the ones on the road here are underground, while the ones right next to them on the pavement are above ground. The level number alone says nothing about which lines are really connected.

ProblemTrusting the level value connects things that do not meet, or splits things that do.
Fix: use levels only where polygons overlapA level matters only when another sidewalk object overlaps this one. If nothing overlaps, ignore the level and treat the polygon as ground level.

Levels caused by other objects

Here the walkable area is a higher level for a reason that has nothing to do with sidewalks: it passes over water. Nothing walkable lies below it, yet it still carries a different level from its neighbours.

ProblemA different level number makes it look disconnected from the pavement it plainly joins.
Fix: same rule, overlap not levelNo sidewalk polygon overlaps it, so its level is ignored. It touches its neighbours, so it connects to them.

Touching versus overlapping

Cases 2 and 3 share one proposed fix. Replace "same level number" with geometry. Drag the slider to move the second polygon.

Gap
No link. Touch
Link the two. Same network, so you can walk from A to B. Overlap
Separate layers, one above the other. No link at the overlap. Each layer can still link to other polygons that only touch it.

Working approach so far

  1. Skeletonize every walkable polygon.
  2. Filter polygons whose neighbours are all roads. Keep them for crossings only.
  3. Detect overlaps between sidewalk polygons. Only overlapping polygons get separate layers. Ignore the BGT level otherwise.
  4. Connect by touching: polygons that share a boundary join the network, including across layers if they touch rather than overlap.
